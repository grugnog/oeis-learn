# Grounding, proof and discovery contract

Sources inspected: uploaded independent review §§3,5,17–19 and current `src/oeis_learn/{decoder,discovery,data}`. Normative for FR-021–023 and FR-031–033. This specifies future implementation, not measured performance. All paths below are relative to the repository. All capabilities are included within 007, with staged activation after correctness gates; none require LODA or imported program supervision.

## Immediate repairs: constant grounding

Adapt `decoder/constant_solver.py`, `decoder/dixon_solver.py`, `decoder/qfnia_solver.py`, `decoder/mersenne61_filter.py`, `data/models.py`, and both callers (`rl/trainer.py`, `evaluation/synthesis.py`). Introduce one `GroundingService` over the shared typed program IR and shared final-candidate execution pipeline; legacy public entry points become adapters to this service, not divergent solvers.

* Logical placeholders identify mathematical i256 constants before lowering. Never abstract preamble limbs, shifts, loop-structural literals, or helper internals. Canonical placeholder identity is stable across parsing, substitution, and proof artifacts.
* Dependency analysis distinguishes parameter-independent values, affine expressions in parameter vector, and unsupported/nonlinear expressions. Multiplication is affine only if at least one operand is parameter-independent. Branches/loop trip counts depending on parameters, parameter divisions/remainders/bit operations, and nonlinear recurrence unrolling cannot enter the affine solver. The analyzer is conservative: inability to prove affine means another supported tier or `UNSUPPORTED`, never an affine guess.
* For the affine subset, derive exact coefficient expressions and offsets symbolically, evaluated at the visible indices. Use exact rational elimination with integer-integrality checking, or genuine integer normal forms; remove `numpy.linalg.lstsq` and all float64 coefficient/term conversions. Persist actual method names. A uniquely determined rational noninteger solution establishes no integer solution for that exact equation system. Rank deficiency dispatches bounded integer constraints/enumeration, rather than declaring unsatisfiable.
* The modular method retains exact candidate checking but tracks actual pivot columns and row indices. An unlucky prime/rank reduction/reconstruction outside the chosen coefficient range is not unrestricted integer UNSAT. An inconsistent faithfully translated modular system can reject the corresponding exact integer system; store its matrix/modulus and checker evidence. Retry a bounded recorded prime list or fall back to exact elimination; record budget exhaustion distinctly.
* Recognize constant-coefficient linear recurrences from proven state-update/dataflow structure, initial conditions, indexing, and invariant coefficients. Infer recurrence order from lag-state dependencies, never placeholder count or loop substrings. Cache lag matrices using prompt digest, index set, order, and transform hash. The linear coefficient fit for a recurrence is a property of this recognized class, not proof arbitrary loop output is affine in parameters.
* The nonlinear tier must actually call `qfnia_solver.py` and assert bounded Z3 Int constraints generated only for its supported arithmetic/control subset. No silent use of the old 64-bit BV translator while labeling the result QF_NIA. A separate BV tier may model exact native-width operations, with explicit signedness, traps, and checked-wide range constraints. Initially unsupported loop/symbolic-divisor encodings return `UNSUPPORTED`; finite bounded enumeration is a valid generic fallback and cannot claim UNSAT after incomplete search.
* Every solver result carries `VERIFIED_SOLUTION`, `PROVED_UNSAT_IN_SCOPE`, `UNKNOWN`, `TIMEOUT`, or `UNSUPPORTED`, plus coefficient bounds, semantics, fitting indices, elapsed time, and reason. Scoped UNSAT requires complete exact constraints or exhaustive completion of the recorded finite search domain. Z3 `unknown` is not timeout unless the reason says timeout.
* Reparse/typecheck/substitute the complete candidate; execute all fitting terms through production and independent reference semantics, with exact output length and no hidden terms. Only then allow reward/replay/elite admission. The no-placeholder path also executes and verifies. Counterexample-guided retries use only visible fitting evidence and count toward the same frozen proposal budget.

Acceptance: C*C with target 4 either finds ±2 or reports unresolved; C=4 never admitted. Include large/signed coefficients above 2^53, underdetermined but integer-solvable systems, nonintegral unique solution, unlucky modular prime, incorrect pivot-order reconstruction, parameter-dependent loop, division/trap cases, more placeholders than supported, timeout vs unknown, no-placeholder mismatch, and identical training/evaluation dispatch. Assert actual configured solver prohibition/enabling is effective and durations are measured at source.

## Immediate repairs: both symbolic prover APIs

Adapt `discovery/symbolic_prover.py`, `data/symbolic_definitions.py`, `data/models.py`, and report consumers/tests. Fix `prove_relation` as well as `prove_canonical_relation`; quarantining only the newer strict API leaves the known defect live.

* Parse a bounded allowlisted expression AST, constructing expressions from a single canonical `n = Symbol('n', integer=True)` object. Do not pass untrusted formula strings directly to unrestricted `sympify`. Restrict input size/node count/depth and run simplification in a killable bounded worker.
* Registry parsing validates schema, declared variable set, expression/source content hashes, provenance, definition domain, and index convention. Parseability does not establish a definition is true of an OEIS sequence; record a reviewed definition as an assumption unless separately certified.
* For each operand, compute the preimage of its domain under `scale*n + shift`, including sign of scale and the constant-index case; intersect operand domains and exclude poles/undefined points. Retain original denominator exclusions before cancellation, so `(n-1)/(n-1)` does not silently gain n=1. Unsupported domain reasoning yields `UNKNOWN`. An empty common domain reports `EMPTY_DOMAIN`, not a useful identity proof.
* Normalize exact polynomial/rational identities with bounded procedures. Zero residual can produce `FORMULA_IDENTITY` scoped to assumptions/domain, but cannot by itself establish program semantics or the OEIS definition. A nonsimplified residual is `UNKNOWN`. `COUNTEREXAMPLE` requires a concrete in-domain integer index, defined exact operand values, and nonzero residual.
* Persist expression hashes, exact index transforms, domain/exclusions, assumptions, backend/version, normalized residual, witness or certificate, and diagnostic. Remove generic unqualified `PROVEN` output from both APIs; use explicit evidence kind plus verified scope. Compatibility reports map old labels explicitly to legacy/untrusted, never silently promote.

Acceptance: same-printing symbols with different assumptions, a false shifted n identity, negative index shifts and scales, zero scale, disjoint domains, removable and genuine poles, unknown simplification, malformed registry hash, malicious/unsupported expression forms, timeout, true polynomial identities, true rational identity with excluded points. Test rendered reports cannot erase domain/assumptions.

## Included broader improvement: generated-program discovery

Adapt `discovery/pipeline.py`, `discovery/vector_search.py`, `discovery/relation_identity.py`; add bounded `discovery/program_features.py`, `discovery/program_archive.py`, and `discovery/transforms.py` (names are proposed). The pipeline must consume admitted generated programs and their actual decoder/model provenance, rather than discarding the loaded decoder and treating term embeddings plus known formulas as program discovery.

* Archive many distinct implementations per sequence: normalized IR/source hash, compiler/semantics/model hashes, input/fitting/continuation manifests, costs, genealogy, and finite/proof evidence. Keep a bounded Pareto set for training and a content-addressed archival record for long valid programs exceeding model context. Same-output dedup does not discard distinct algorithms from discovery.
* Extract scope-aware alpha-normalized subtrees, dataflow edges, recurrence-state signatures, bounded loop summaries, and semantic fingerprints at fresh declared indices. Similar code/fingerprints propose relationships; they never prove them. Fingerprint data unavailable to training/evaluation stays in the separate post-evaluation analysis role.
* Implement bounded operator adapters for shifts/reindexing, difference, partial sums/products, interleaving, convolution, and composition over typed programs. Record whether the proposal came from a model feature, literal shared fragment, or a hand-specified operator. Each adapter has finite construction and execution limits and independent positive/negative fixtures. Composition must check domain/range; sums/products/convolution obey checked arithmetic and resource limits.
* Canonical rewriting uses typed AST rules with explicit side conditions and exact trap/effect semantics. Start with a small checked rewrite catalog; equivalence saturation is optional internal scheduling, not a required new dependency. Validate every admitted rewrite against an independent checker for its supported domain. Do not apply unbounded-integer cancellation/distributivity through a potentially trapping fixed-width intermediate without range proof.
* Freeze a conjecture and evidence before post-hoc novelty lookup. Record known rediscovery/new implementation/empirical conjecture/certified relationship separately. Imported formulas, programs and literature references are analysis evidence only, inaccessible to strict bootstrap/model/search. A new implementation is not automatically a new mathematical relationship; lack of a retrieved match is `novelty_unknown`, not proof of novelty.

Acceptance: two different implementations of one output sequence remain available for feature analysis; a discovered relation cites actual generating programs/features; one positive and adversarial negative fixture per operator; trap-sensitive rewrite counterexample; discovery cannot access private final truth until evaluation has been sealed; known-reference lookup cannot alter the already-frozen proposal or strict training pool.

## Included broader improvement: scalable exact relation search

Adapt `discovery/vector_search.py`, `discovery/pslq_solver.py`, `discovery/numerical_validator.py`, `discovery/relation_identity.py`, and discovery configuration. Integer sequence relation search no longer routes through one-index PSLQ.

* Use bounded-neighborhood candidate retrieval and blockwise top-k over numerical signatures, normalized program features, or learned retrieval features. Explicitly cap neighbors, pair hypotheses, arity, block memory, total attempts, and wall time. Rank globally among the considered budgeted proposals with deterministic tie breaking; never return the first 50 by traversal order. An O(N²) blockwise baseline with bounded candidate refinement is sufficient to remove cubic enumeration and supplies a simple reproducible reference. ANN is an optional implementation, not necessary system infrastructure.
* Do not assert normalized synthesis embeddings preserve addition. Compare program/numerical features against synthesis latents using the same frozen proposal budget and labeled diagnostic relations, recording precision, recall, and candidate attempts. A retrieval head can be trained only on allowed generic/verified-training provenance.
* For candidate arity <= 8, build an exact integer matrix at all configured fitting indices and compute rational nullspace/rank; clear denominators and normalize by gcd/sign. An integer nullspace basis need not contain the sparsest or smallest-bounded relation: bounded coefficient search can combine basis vectors, with fixed enumeration budget and `UNKNOWN` when incomplete. Compute support size; claim minimal support only after exhaustive proper-subset checks within this small arity, otherwise null/unknown.
* Reject malformed length pairs before zip/canonicalization, zero relation, and duplicate operands after combining coefficients; include index transforms in identity. Coefficient bounds and any lattice reduction are recorded. PSLQ remains only for explicitly approximate-real constant problems with its own precision/error contract; it is not a proof backend.
* Require pairwise-disjoint, nonempty fit/validation/final index sets and sufficient available terms at the actual indexed source offsets. No empty-partition success. Freeze coefficients before validation, then freeze selection before final analysis tests. Reuse of final indices is recorded as exploratory and cannot receive confirmatory status.
* Compute actual rank, nullity, residual vectors, source digests, transformed index coverage, coefficient method and attempts. Null is preferable to invented rank=0/minimal_support=true/zero source hash. Include shuffled unrelated negative controls and report search multiplicity.

Acceptance: relation that holds at index15 only fails; changing configured fitting indices changes the matrix; empty/overlapping/missing partitions fail closed; exact wide-integer dependencies succeed; limited basis search does not claim UNSAT; permutation order does not change global retained top-k; altered source hash invalidates evidence; planted relation recall and randomized controls measured for N=128,256,512 under fixed feature width/k/arity, with operation counts proving bounded pair work and reported runtime/memory (no universal speedup claim).

## Included broader improvement: scoped replayable proof certificates

Add `discovery/certificates.py`, `discovery/certificate_checker.py`, and class-specific modules. Evidence records distinguish prefix fit, independent finite validation, bounded machine verification, formula identity, and certified program-class theorem. A general mathematical theorem requires a supported independently checked argument linking definitions/programs and assumptions; no generic `PROVEN` flag.

Implement these deliberately bounded certificate families in 007:

1. Polynomial/rational expression programs: extract an exact expression from straight-line typed IR; check coefficient-normal-form equality, domains/poles, and operation range conditions. Certificate ties IR and generated code hashes to a checked lowering contract. Unknown input range or unchecked lowering means formula identity only, not machine theorem.
2. Constant-coefficient linear recurrences: verify recognized state transition and initial states; for identities combine recurrences using a common annihilator and verify the sufficient initial segment, or provide a rational-linear state-space invariant checked by exact matrices. A recognizer cannot assume recurrence from sampled outputs. Integer-sequence theorem is separate from the finite safe machine range.
3. Finite-state periodic generators: enumerate a declared bounded reachable state space, verify transitions, initial state, repeated-state cycle, output mapping and closure. State limit exhaustion is `UNKNOWN`; a few repeated outputs are insufficient.
4. Restricted loop invariant certificates: accept explicit affine/polynomial invariant and ranking-function candidates for a restricted loop IR. Check initiation, consecution, exit/postcondition, decreases/nonnegativity, and checked arithmetic range preconditions with exact algebra/SMT. The first candidate proposer uses bounded templates, not an unrestricted automatic invariant synthesizer. Unsupported operations yield `UNSUPPORTED`, failed proof obligations `UNKNOWN` unless concrete counterexample evidence exists.
5. Bounded machine equivalence/property: exact enumeration for tiny finite index domains or SMT under a fixed supported transition/unroll bound. Persist domain/unroll/overflow/termination assumptions and solver replay script; bounded evidence is never relabeled an all-index theorem.

For compiler linkage, validate each supported lowering helper and typed control translation independently; instantiate its checked contracts in a certificate. Differential testing alone is not a formal compiler theorem. If only differential tests are available, retain separate mathematical-IR theorem and finite compiled-WASM conformance evidence without promoting to a proved WASM theorem. Unsupported arbitrary WASM/loops can return `UNKNOWN` in the implemented proof API; this is a bounded capability limitation, not a postponed implementation item. General-purpose Lean/Coq integration is not needed to implement these supported proof families and should not be presented as a promised repair.

Acceptance: replay certificates in a fresh process with no model weights; mutate coefficient, initial state, domain, compiler hash, overflow assumption, invariant or certificate and observe rejection; accept one hand-checkable positive per class; reject finite-match impostors; reject wrong recurrence/order and nonterminating-loop ranking claim; propagate unknown on resource exhaustion. Reports expose theorem semantics (mathematical integers, modular words, checked machine) and every unresolved link.

## Dependency and budget guidance

Repair legacy proof false positives and final grounding admission immediately after shared exact semantics; do not postpone them until discovery redesign. Structural solver tiers then enable after independent regressions. Program archive and typed IR precede feature/relation search; exact numerical validation precedes certificate promotion. Post-hoc novelty stays last. Use the same artifact/config/checkpoint/provenance framework; no separate orchestration stack. Unit/contract fixtures and one combined analysis acceptance suite suffice; broad experiments or multi-day proof sweeps are unnecessary.

For initial defaults, bound solver parameter count to 8, coefficients to ±1000, symbolic worker wall time to 2 seconds, relation arity to 8, and proof worker wall time to 10 seconds with independent memory limits; all are declared profile fields and changed only via new profile identity. These are planning defaults, not empirically optimal thresholds. Large exact constants remain legal literals even when bounded solver synthesis cannot discover them. A cap is an unresolved resource outcome, not a mathematical disproof.

Research pointers already provided by the review: grammar-aware program synthesis and multiple implementations, https://arxiv.org/abs/1805.04276 ; equality-saturation infrastructure, https://arxiv.org/abs/2004.03082 . These motivate techniques; neither establishes performance or proof soundness for this codebase.
