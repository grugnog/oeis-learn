# Dataset, information-boundary and scoring contract

Normative for FR-007–013, FR-019. Profile `prefix20_total100_v1`; all persisted integers use canonical decimal strings, including negative values. Source bytes and canonical artifact contents have distinct SHA-256 fields. No formula, name, tag, offset or sequence identifier is a model feature.

## Eligibility and grouping

1. Ingest a pinned local source snapshot. Verify original index continuity for the first 100 terms starting at the source's declared first index. Missing indices, duplicate conflicting indices and gaps are exclusions; do not infer an index from a display label. Keep a reason for each excluded record.
2. Require each of these 100 values to be in `[-2^255, 2^255-1]`. Record available-term coverage separately from complete-100 coverage; report total records, complete records, in-range complete records, groups and selected representatives. Do not report a prefix-only census as full-horizon coverage.
3. Build an undirected graph over eligible records. Add edges for equal 100-value arrays, equal first-20 prefixes, or a verified shift by d=1..20 in either direction where **all 100-d overlapping terms** agree. Use hashed 80-term windows to find shift candidates, then compare the entire overlap exactly; hashes alone do not establish an edge.
4. Connected components are split groups. Group identity hashes sorted member source/record IDs and grouping-profile identity. Record sufficient exactly verified witness edges (kind, shift, matched overlap) to reconstruct each component. In an identical-array/prefix bucket, union each member with one representative; do not materialize every pair. Deduplicate already-connected shift candidates and retain witness edges rather than a quadratic all-pairs archive. Transitive grouping is intentional and may make large groups; report group-size distribution. The release additionally groups the exact affine/shift transformations below; this is still not general mathematical equivalence and does not cover arbitrary binomial transforms.
5. Representative is the lexicographically smallest source-qualified OEIS ID in each component, chosen without model performance. Sort groups by SHA-256 of canonical `[split_seed, group_id]`; assign the first configured `dev_count`, then `final_count`, and keep remaining groups reserved. Default future-comparison request is 128 development and 512 final; 007 tests use small declared fixture counts. Insufficient groups is an error, never automatic resizing. Seed default 20260913; counts/seed are frozen in the manifest.
6. The representative is the sole primary scoring unit. Nonrepresentative and ambiguous-prefix records remain in evaluator-only artifacts; optional secondary reporting must name its different denominator. No selection by easy family, known implementation or reference solver success.

## Information boundary

Artifact views are separate files and process inputs, not a single object with fields callers are asked to ignore:

- Evaluator truth: original indices, 100 values, OEIS/source IDs, group edges/members, split, eligibility and source provenance. Accessible only to the cohort builder and scoring process; never mounted into learner or generation workers.
- Generation prompt: twenty exact values, language/profile ID and an opaque per-evaluation request nonce. The model receives values only; the nonce routes results and cannot encode an OEIS ID. No truth hash, name, family, offset or group metadata enters tensors, prompts or scaffold selection.
- Strict admission: a service accepts a generated program and independent outputs. An evaluator-owned exact hash set of the **first twenty values of every member** in development/final groups blocks collisions. It returns a boolean/reason only, not a matched ID or continuation. No learned or similarity-based holdout filtering.
- Trainer view: approved program ID, codec/profile IDs, twenty conditioning values and body tokens. Full synthetic outputs/evidence stay in the admission archive. Synthetic continuations are computed from generated programs, not borrowed from OEIS.

The evaluator must not leak per-candidate hidden feedback until the proposal list and selection are sealed. Generation runs in a process/container that never receives the hidden artifact or its mount. A developer with host access is outside this accidental-leakage boundary; it is not a claim of cryptographic secrecy against the operator.

## Evaluation protocol and sealing

Load and hash the exact requested checkpoint; reconstruct architecture and codec from its manifest and verify compatibility. Use one greedy attempt followed by up to 15 seeded stochastic attempts at temperature 0.8, top-p 1.0, with the execution contract's time/token limits. These are foundation defaults, not a language-comparison result. Deterministic fixtures can declare smaller budgets in a different test protocol.

Candidate seeds are derived from canonical `[run_seed, sampling_profile_hash, prompt_hash, attempt_index]`, using the first 64 bits of SHA-256 as an unsigned integer. `sampling_profile_hash` hashes only public language/codec IDs, decoding settings, selector and budgets; it excludes run/contract/checkpoint/cohort/truth hashes and any digest that transitively contains hidden values. The private evaluation protocol may reference those identities, but its whole hash must never seed generation. A prompt hash contains the visible values only. Duplicate prefixes intentionally receive identical sampling seeds in a given protocol; hidden identity never changes generation. The baseline disables fitting. A qualified solver/search variant may use only the same twenty visible values; its immutable sampling profile names this change. Metadata scaffolds, pretrained weights and reference fallback remain prohibited.

Before accessing hidden truth, seal an ordered candidate manifest containing source hashes, prefix evidence, attempt seeds/order, generation completion status and the selected candidate. Select among prefix matches by `(predicted_body_token_count, source_sha256)` ascending. This deterministic tie break avoids hidden feedback and timing-noise selection; speed remains a separately measured metric. If none matches, selection is null. Reference programs may validate the evaluator in isolated fixtures; they cannot fill a missing model candidate.

Development evaluation may inform checkpoint/experiment selection, but its hidden terms cannot enter training examples or per-prompt generation. For final evaluation, create an immutable finalization decision lock with checkpoint hash, protocol/cohort hashes, selector, stopping decision and run-budget ledger hash **before** opening final values. Final evaluation then generates from visible final prompts and commits a separate immutable seal for each target; scoring that target requires its committed seal. The final report references the decision lock and every seal. Write one final report for that finalized identity. A resumed interrupted evaluation reuses committed seals and idempotent attempt IDs. Before a target has a seal and before its hidden feedback is accessible, generation may resume from saved public state; after sealing it cannot regenerate candidates. Hidden feedback without a valid committed seal invalidates that final evaluation. A later change creates a new exploratory result, disqualified from that frozen final comparison.

## Scores and failures

For N frozen representative groups, define `success_any = sum(any qualifying full match in sealed budget)` and `success_top1 = sum(selected candidate is a qualifying full match)`. Rates use the same N. Every target remains in the denominator when model syntax, arithmetic, fuel, reference or wall limits fail. Cohort corruption/incomplete truth and missing/incompatible checkpoints invalidate the evaluation, rather than shrinking N or returning a success rate of zero.

Budget exhaustion and partial execution are explicit non-successes. Infrastructure loss (e.g. missing artifacts or controller crash) makes a report incomplete/unqualified until the same sealed evaluation can be resumed; a recoverably killed candidate worker is a recorded attempt failure under the protocol. Report prefix match, full match, unknown due to limits, syntax and runtime failure counts separately. A limit does not imply no valid program exists. No aggregate report may conceal missing targets by using the count of finished targets as its denominator.

Record exact output arrays or their content-addressed evidence, first mismatch index, runtime/profile/checkpoint/source identities and measured costs. Full match is finite evidence only. Proof and novelty status remain `not_claimed`.

## Release source policy, transformed groups and structural holdouts

Before freezing the release cohort, record explicit source database/file paths and hashes (never choose oeis_corpus versus oeis_learn by an implicit fallback), signed offsets, keywords, finite-sequence status and table/flattening convention. Missing/ambiguous index convention is excluded with a reason. A declared flattened table is eligible as that one-dimensional ordering, with its convention preserved privately; unspecified flattening is excluded. Finite sequences qualify for a horizon only when that many genuine indexed values exist. Do not pad or extrapolate source truth.

Compute separate 20/50/100/120 horizon reports: total source records, complete records at that horizon, exact signed-range eligible complete records and exclusions. Also report available-prefix coverage with its own named denominator. Growth descriptors use all observed indexed values/differences under a versioned descriptive rule; last-term bit width alone is never called a growth class. No claim of asymptotic growth follows from these diagnostics.

Extend split grouping to exact nonzero rational affine value transforms combined with shifts <=20. For each compared overlap vector, subtract its first value; divide the difference vector by the gcd of absolute nonzero differences, normalizing sign by its first nonzero element. Equal normalized vectors propose an affine relation; confirm exact rational scale/offset on the entire declared overlap. Constants form one separate component. Preserve witness edges and the original equal-prefix ambiguity groups. Hash windows and normalized signatures, never scan all pairs. This covers a declared class, not arbitrary mathematical transformations. Training admission also excludes normalized first-20 affine collisions with reserved members; this private check reveals only membership/reason.

Generic program split groups use alpha-normalized typed structure with literals replaced by typed slots and control/data dependencies preserved. Freeze group assignment before sampling parameter instances (80% training, 10% synthetic development, 10% synthetic final by digest of seed+signature). Within training structures reserve the upper signed-width bin (128/256-bit constants) for a separately reported parameter-generalization diagnostic, not training examples; lower bins remain training. A separate frozen operator-composition holdout manifest is disjoint from training constructors. Model input never contains signature, group or family labels. Report ordinary identity, unseen-structure, parameter and operator-composition performance separately. These synthetic splits are distinct from the OEIS group split and may not leak generic synthetic final examples into updates.
