# Exploratory selector audit

Authorized after review of completed `pac-012-bcd-r1-002`. This is a new diagnostic
scope on a separate stack above #64, not an amendment to its scientific policy.
The original structural outcomes have already informed this hypothesis.

## Decision and boundaries

Determine whether visible-only candidate ranking can avoid exceptional branches
unobserved in the prefix. No training, fitting, candidate edits, 100-term execution,
new seeds, cohort generation, assessment access or production-policy replacement.
The host command uses Python standard library only. It reads two explicit ZIPs,
never extracts private originals, and exclusively creates a fresh output directory.
Original inputs are immutable. Public diagnostic output contains generated source
identities, branch counts and existing outcome joins, never prompt terms, private
paths, native assignments or model weights. Software success is not scientific
confirmation or permission to adopt a policy.

## Candidate and provenance contract

Verify the original report through the canonical offline verifier. Bind plan and
workflow seals, original producer inventory bytes and scoring/training identities
to that report. Restrict detail ZIPs to the requested eleven files; enforce member,
expanded byte, JSON and path bounds. Reject duplicates and nonfinite JSON values.

For each B/C/D task, reconstruct the *correct-input* portfolio's original eligible
source set from the retained plus omitted archive IDs, recovering source text from
retained records and native assignments. These are original eligible candidates,
not every solver proposal or a union with controls. Recompute the original
visible-only/v2 shortest-byte/source-hash choice; reject mismatches or incomplete
source reconstruction. Require a consistent verified 20-term visible prompt.
The experiment's roster, category, family, scores and control outcomes never enter
the ranking function. Separate outcome attachment happens only after ranking.

## Experimental rule: visible-branch-coverage/v1

Use the existing independent reference interpreter with optional stable branch-site
observation. Record both `if` decisions and `select` value choices; `select` remains
eager, as the language requires. Statically register nested sites, including sites
never reached. Count missing true/false outcomes at every site over precisely the
20 visible indices. Loop counts are not branch coverage and no path-completeness
or causal relevance claim is made. Even a dead/output-irrelevant branch is penalized;
this is an explicit syntactic prior to validate on training probes.

Recheck exact visible agreement. Rank by `(missing_branch_edges, AST_nodes,
literal_bits, source_sha256)`, with no learned weights or task-specific constants.
Do not erase guards, penalize a particular index, or infer unseen values. A fully
observed legitimate piecewise candidate has zero missing edges. Ties are deterministic.
If any candidate's bounded observation is unavailable, retain the original selection
and label the alternative incomplete; do not reward missing evidence.

Diagnostic observation has its own finite work/time ceilings and measured cost;
it is not silently charged to or substituted into the original 60-second portfolio.
A future experiment must freeze its full selection overhead and budgets separately.

## Outcome interpretation

Join an alternative only to a completed recorded score for the *same task and exact
source hash*, across original controls. A censored score is unavailable, not false.
Conflicting completed scores reject the audit. A source with no recorded complete
score is `UNSCORED`; it cannot be counted as correct, wrong or completed execution.
Report known recovered successes, known regressions, unknown changed choices,
coverage failures and original denominators separately. Summaries are exploratory;
no alternative family-macro point estimate or completion-gate PASS is manufactured.

## Validation and subsequent work

Independent tests cover nested/unreached branches, local-dependent predicates,
eager select, loops, resource exhaustion, exact large integers, legacy observers,
input permutation, forbidden outcome fields, score-blind selection, unknown and
conflicting joins, malformed/tampered ZIPs and immutable outputs.

After the audit, use existing fixed B/D checkpoints and *training-only* probes to
validate the rule, including legitimate piecewise cases and regressions. Freeze
policy identity, checkpoint identities, cohort/exclusions, seeds and costs before a
fresh structural selection comparison. Generate each arm/control's candidates once
and apply both selectors to the identical eligible set. Keep the seven controls,
family-macro endpoint and required completion accounting. The sealed assessment
remains untouched. No hyperparameter search is part of this implementation.
