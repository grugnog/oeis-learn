# Cleanup acceptance contract

The maintainer supplies a comparison for each deletion group. The campaign operator supplies private-original or device evidence where the affected behavior requires it. An independent reviewer checks the resulting report and its supporting records. Use the pinned control for the particular operation under review. ## Group review and release checks

| Change touches | Required comparison |
| --- | --- |
| Output, document or duplicate guidance | Trace incoming links, filename patterns, directory consumers, exact hashes and cited results. Check the replacement covers supported instructions and survives packaging if appropriate. Compare the observable consumer before/after. |
| Python symbol, script or config | Trace imports, CLI defaults, explicit operator paths, registries, CI path lists and subprocess/filename loading. Check surviving public signatures, negative cases and dependent defaults. Report source-map and image-context membership separately. |
| Installed, native or build input | Compare both wheel routes, installed inventory/entry points outside the checkout and the native identity when affected. Run the existing relevant qualification/native partitions and retain their receipts. Exercise Docker CI and local Podman paths proportionally to the change. |
| Each source-changing group, including inputs to the source map | Compare group parent and candidate. Validate the round009 donor against untouched qualified `77667e67` and a disposable qualified copy with its own Git root. Before validating the copy, require its changed source-map keys and change types to match the independent parent-to-tip comparison. Record the paths/hashes and candidate-specific result. Hold any rejected or untestable transition. |
| Source/proof bound to an accepted campaign | Reproduce the previous operation at its exact pinned source. For a changed fresh source, establish applicable new qualification. Preserve original producer hashes, allowances, bytes/inodes and the recorded qualified-versus-diagnostic distinction. |
| Entangled obsolete behavior or outstanding evidence | For a deprecation, name the obsolete command/path/symbol, live dependency at risk, supported replacement if any and reconsideration condition. Follow the note or direct pointer in a surviving tracked operator guide or index from the candidate checkout. Preserve authenticated bytes. A held group records its missing evidence in the review record. |

A group record includes its parent and candidate revisions, observed results and rollback commit or procedure. Record pre-existing differences separately. The local baseline sdist omitted the spec 005 CLI contract from its source map. Reproduce that pair in the matching release environment for any packaging-sensitive change. The four workflow checks apply to the combined cleanup. Individual groups need the checks for the contracts they can affect. [Source comparison and limits](../research.md)
