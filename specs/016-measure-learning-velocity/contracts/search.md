# CPU structure and search contract

**Decision.** If a structure is supplied, can the current fitter recover its continuation? If it can, does a fixed or prefix-conditioned search find admissible programs early enough to improve the single submitted answer? Run the privileged test while preparing the training screen. It has its own CPU work reservation.

## Permitted inputs and comparisons

| Role | Inputs | Measure |
| --- | --- | --- |
| Private practice preparer | Disjoint synthetic practice families, executable witness, verified typed skeleton and private coefficient map | Independent witness, projection audit and exact indexed record |
| Known-structure fitter | Verified structure with unknown values removed, permitted structural constants, the true 20 indexed values and registered fitter | Continuation of one visible-only grounding, elapsed work and fit disposition. An independent scorer opens the suffix after commitment. |
| Guide teacher | Eligible generic training families, verified positive derivations, admissible alternative programs and training-only suffix verification | A frozen guide, identity of positive steps, coverage, teacher/fit work and total cost |
| Fixed order / true guide / shuffled guide | Same practice or development prompts, typed action menu, frontier policy, selector, inference budget and visible-only eligibility | First verified-correct admission, matched-work coverage, one selected exact solve, paired outcomes and costs |
| D reference | Normal qualified model inference with only its allowed input, on the same cases and total opportunity | Direct selected-yield and time comparison. Share compatible D receipts once, otherwise use the physical device lease. |

Build the privileged projection from authenticated AST occurrences and parameter-sharing metadata. Independently account for every residual literal as a permitted structural value, such as a visible offset. The native eligible-literal abstraction stops after eight eligible occurrences and preserves control-tainted literals. Running it alone on an arbitrary witness could reveal unknown coefficients. Mark over-cap, unrepresentable or unverifiable projections as unsupported. Record zero-unknown cases separately. The practice scorer distinguishes exact recovery, completed failure, unresolved, unsupported and witnessed ambiguity. Ambiguity requires two independently executed legal groundings/programs that agree on the visible 20 and disagree later. Solver status or one timeout alone gives no such witness. ## Live construction search

1. Represent a frontier item as a canonical typed partial program, holes in a fixed order, applicable grammar actions and stable tie key. Seed it with registered existing generic templates. Extend only legal actions, deduplicate by canonical partial state, and record rejected/duplicate expansions, work and elapsed time. Freeze the operation menu, depth/fuel semantics and search order or guide identity before evaluation. Each emitted complete proposal consumes a portfolio attempt, including a duplicate or rejected one. Fit it through the normal visible admission path. All internal expansions consume wall/work allocation. Any optional subfit that evaluates another complete proposal consumes an attempt and every subfit spends time in the same account.
2. Fixed-order search uses a deterministic action order. The learned variant changes action priorities only. Use a CPU linear score per legal action with a frozen regularization weight, deterministic initialization and masked softmax. Maximize the probability mass assigned to all verified next actions from the state. Train on visible prefix summaries and the typed partial program, including features from closed subexpressions executable with permitted visible information. At a shared state, aggregate verified positive next actions across eligible solutions. Weight training cases/families to prevent one prolific trace from dominating. Leave unexplored actions unlabeled. Freeze feature scales, guide weights, training seed, tie order and fallback on training-only data. The old same-bank selector ranks *finished* programs and remains a comparator for actual selection opportunities.
3. Generate a seeded within-stratum derangement with genuinely different visible donors. For the shuffled guide, compute every sequence-dependent guide feature, including partial execution features, from the donor at the recipient’s indices. Keep recipient data for admissibility, external choice and independent scoring. If a state has no valid differing donor, log an unavailable conditioning contrast. All methods have the same recipient cases and declared end-to-end opportunity.
4. The alternating-subsequence construction is admissible only if the combined program round-trips through the codec and meets the existing execution profile. The language can toggle a Boolean and maintain a pair counter in a bounded loop over `index − visible_offset`. Fit its branch coefficients on all 20 original values. This also handles negative starting offsets. The current polynomial/recurrence adapters validate full-length prompts. Do not pad half-sequences or expose a private witness to make the example work. Retain the fixed-template menu when a composition is unsupported. [Grammar and codec](../../../src/oeis_learn/decoder/bigint_codec.py) · [Conventional producers](../../../src/oeis_learn/generalization/progressive/baselines.py)

Use an installed CPU proposer with explicit prefix-only mounts. Feed it to the normal native fit, final-source execution/admission and qualified selection rules. The old forced-candidate path is privileged and diagnostic. At the full profile the frontier, model calls, subfits, whole-program attempts, admissions and selection fit inside a single account per method. A first-correct timestamp is the time a candidate was actually admitted, later established by private verification. It cannot change the live choice. Report elapsed, expansions/duplicates, model calls, fits, distinct structures, fits completed, withheld verification work, offline training cost and any shared work. Price a serial reference when CPU and GPU would compete for memory or CPU cores.

## Bank and routing evidence

Seal all live methods’ choices before examining suffixes. For a priced, frozen matched diagnostic sample retain each issued ordinal, termination/drain status, source or authenticated alias, fit result and selected membership. The default compact archive can omit alternatives. Reuse the full distinct admitted-source capture and ordinal map where available, preserving empties and incomplete banks. Apply the actual probe profile to the new reader. [Portfolio capture](../../../src/oeis_learn/fresh/bigint_diagnostics.py) · [Historical bank reader](../../../src/oeis_learn/generalization/progressive/program_search_bank.py)

| Evidence after private scoring | Allowed interpretation and follow-up |
| --- | --- |
| True structure frequently fails under the registered allowance | Separate verified visible ambiguity, unsupported representation and reproducible fitting/verification fault. Price a targeted replay or qualified repair. Record ordinary timeouts as uncertainty. |
| Exact witness exists, all allowed live attempts are accounted for, and every admitted source misses | Witnessed proposal failure, including a completed empty bank. Compare fixed and guided construction coverage. |
| Complete eligible bank has an independently verified alternative and the sealed choice is a measured miss | Verified selection opportunity. Compare selectors on the identical bank/order with equal visible information, then price the prospective policy if worthwhile. |
| Fixed order gains over D, or a guide advantage survives shuffling | Credit the solver or sequence-independent ordering prior. Retain fixed order as comparator. A true-guide advantage requires a direct matched comparison with both fixed and shuffled. |
| Correct candidate appears earlier but selected yield is flat, or bank/scoring remains incomplete | Publish evidence on search time and uncertainty. Inspect the smallest matched sample that could change the decision. A trained guide or solver earning further spending can be tested on real OEIS development and subsequently on independently reserved families. |

When several bottlenecks qualify, count each witnessed case once in each documented diagnosis, display overlap, and compare the recoverable family-weighted yield against each branch’s measured marginal hours. If missing bank members or fits can reverse the order, use the smallest registered case/ordinal prefix that could settle it. A selection branch always needs a verified passed-over candidate. Record a repeatable tie order in the freeze.

The CPU result has its own cost and verdict. Its privileged solves, oracle labels and retrospective best candidate never enter the learning curves.
