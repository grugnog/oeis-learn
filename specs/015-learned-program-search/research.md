# Round028 research decisions

These decisions use source and already disclosed round027 measurements. The first executable step seals the diagnostic order and spending rules before opening any additional private case outcome. The unknowns below have a specified treatment. None requires a new workstation run to choose the design.

| Decision | Evidence and rationale | Alternative considered |
| --- | --- | --- |
| Start with an authenticated, CPU-only audit | Six 1M looks and trial 00 at 2M can be joined with the controls on 128 stable case identities. D solved 23 and trial 05 solved 18. Trial 00 solved 11 at each of 1M and 2M, with four gained and four lost. Paired cases can distinguish failure modes that these totals hide. | Another 4M or 16-trial sweep would spend GPU time before identifying an opportunity. |
| Recover complete candidate sets where the evidence permits | The original generator saved private portfolios including draws, fits, native assignments, archive IDs and the selected source. Some archives retained only IDs for discarded programs. A source can sometimes be reconstructed from an assignment, re-admitted on the true prefix and matched by hash. Exhaustive claims require every eligible identity and its observed disposition. Conventional controls may have saved only their selected output. | Treating a missing program as a failed program would overstate the need for a new generator. Rerunning a decoder would measure a new search. |
| Keep the historical 25M runs as scoped evidence | Two seeds each trained on a fixed collection or a collection refreshed during training. The four saved full-state checkpoints total 100,002,752 training tokens. The registered evaluations used diversity confirmation and retention panels. Inventory all four by identity, exposure, panel and policy. Only an already comparable development producer can supply a historical paired row. | Selecting an intervention from old confirmation outcomes or testing all four checkpoints again would consume protected evidence or compute. |
| Fit a small CPU selector on training-only choices | Plausible programs can agree on all 20 inputs and diverge later. Rank a verified positive above a verified, prefix-matching miss from the same training case. A regularized linear pairwise model with prefix-by-program interactions can make a different choice when the conditioning input changes. | A source-length heuristic is a valuable incumbent. A prefix feature that adds the same scalar to every candidate cannot change their order. A larger neural selector would add GPU work before establishing that the choice matters. |
| If generation wins the diagnosis, change one training signal | Ordinary preparation already verifies and parameterizes eligible targets. Use the same positive token sequences, rows and updates in both arms. In the intervention add one preference loss at the first eligible token where a verified positive and a certified training miss diverge. Both logits are available in the original teacher-forced pass. This tests whether verified alternative programs teach the decoder to place better proposals earlier at the same exposure. | Replacing positives with shorter programs is promising but changes the number of supervised tokens or examples per update. Longer training alone would leave the mechanism unidentified. |
| Freeze fresh families and measure difficulty before comparison | The 128 old cases are a subset of a larger exposed development panel. Reserve whole linked families against the full exposure registry. Use disjoint synthetic families with known executable witnesses to calibrate difficulty. OEIS remains a separate transfer measurement. | Selecting the easiest old cases or discarding hard fresh cases after observing a model would change the question. |
| Extend the 013 graph with a versioned paired study | The existing graph, trial and budget journals, verified output binding, freeze cache and full-state recovery already establish ownership. The historical Optuna study has a fixed roster and its terminal feedback requires eligible measurements. Record an exploratory look as an observation on the new study. | Using a historical trial ordinal or marking a partial pilot as a successful formal trial would corrupt the original study. A second scheduler would split ownership and costs. |
| Run candidate code against one physical state authority | Materialize the pinned candidate source separately. Bind all host operations to the original physical workspace for state and its existing GPU lease. Import verified donor files by reference and write only the new campaign and its own receipts. Qualify the actual new source, images and device. | A second checkout with an independent lock could use the GPU concurrently. A symlink to run-state conflicts with the existing confinement rules. Copying the entire donor would duplicate large models and journals. |
| Separate private replay from public verification | On the workstation, independently replay private executable choices. Publish disclosure-reviewed sufficient statistics and integrity receipts so the archive-only verifier can recompute the reported counts, uncertainty, verdict and action. The 013 exporter can embed whole compressed producers. | Reusing that encoding for complete candidate banks could publish private sequences or program source. A report consisting only of a verdict hash cannot reproduce the statistics. |

### Inputs acquired at execution

The implementation will collect the actual donor closure and its disposition, current filesystem capacity, fresh family supply and eligible training pairs. The accepted production rehearsal will measure GPU activity and lease time by phase, cold starts, slow valid fits, peak intermediate storage, recovery overlap and publication size. These quantities decide which registered work is feasible. An unavailable sampler, incompatible donor or insufficient set of fresh families has an explicit outcome in the [experiment](contracts/experiment.md) and [operations](contracts/operations.md) contracts.
