# Read-only pilot diagnostics v1

The main CLI `oeis-learn pipeline pilot-diagnose collect|models` implements a
separate post-run scope, never learning/resume, calibration admission, checkpoint
selection or final-cohort access. The portable foundation CLI shares this code.
Historical study records and budgets are immutable. Diagnostic results are new
observations, not recovered original logits/gradients or renewed expired attempts.

`collect --run PATH` accepts a verified public run directory or archive and needs
only host stdlib. It summarizes all available milestone validation histories and
training bins, full-denominator arm outcomes, failure/deadline dispositions,
selected-program diversity, native boundaries and resource/timing observations.
Missing milestones stay explicit. Originals are read-only; outputs are fresh.

`models --run FULL_RUN --admission FULL_ADMISSION --inputs FULL_PRODUCER` includes
collection and imports actual saved ordinals0–5 from the accepted full-clock v3
pilot. All six are default; explicit unique sorted subsets are independently
identified and earlier-selected versus immediate-earlier references are disclosed.
Verify bundle bytes, source/study/work/approved authority/cost/qualification,
public trainer/audit/pointers/record/weight hashes and prepared visible examples
before engine access. No reconstruction, retraining, trained-state substitution,
optimizer loading or weights fallback. Source compatibility permits only explicit
new diagnostic modules, routes and owning tests/contracts; all model/encoder/
decoder/codec/data/native/recipe/math dependencies remain identical. Current
installed package inspection, owning CPU/native and actual-HIP fixtures precede
snapshot probes in the same invocation. CPU mode is explicit; HIP never falls back.

Each serial snapshot role loads restricted tensor-only weights, validates actual
model counts/FP32/math, and runs eval/inference mode with unchanged parameter
digests before/after. Inputs contain only visible20 generic examples, canonical
program labels, frozen recipe, public descriptors and verified weight tensors.
Never mount hidden100-index truth, OEIS/final examples, optimizer or full resumable
checkpoints. Outputs contain IDs/scalars/aggregates, not weights, raw training
examples, source bodies, logits or activation arrays. Tensor summaries are not
causal explanations or full-matrix rank claims.

Default per-example teacher forcing covers all32768 training plus128+128 generic
development rows. Optional lower training-row cap uses deterministic ID hashing,
records actual IDs/strata/denominators and is explicitly a subset diagnostic.
Correct-conditioning losses, nonpadding token accuracy, canonical exact match,
entropy and error-token categories are emitted for every planned row. A missing
or timed-out row is not a zero loss or negative semantic result.

The matched conditioning roster is the frozen32 training panel and full128+128
held-out generic rows. For each, compare correct, seeded fixed within-split
shuffled inputs and the existing one-valid-token absent marker against identical
canonical targets, batch16, numerical policy and token normalization. These are
teacher-forced interventions, not new100-index continuation scores. Report paired
loss/accuracy differences. Hidden/evaluation outcomes never alter data/snapshot
selection. Activation statistics use a fixed deterministic64-row panel with scalar
summaries per transformer block/memory/logits; no full activation retention.
Weight summaries compare every state tensor against initialization and the
previous selected milestone: finite/zero fraction, norms, cosine, maximum change,
relative change with explicit undefined-zero references. Optional spectra are
bounded64x64 deterministic submatrices of at most32matrices; label sampling and
never call them full-matrix singular spectra.
