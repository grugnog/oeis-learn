## Finite schedule and interpretation

Run exactly `cold`, excluded `warmup`, `calibration-0`, `calibration-1`, `calibration-2`. Each is a fresh isolated role with fresh baseline KV caches. Warmup is an excluded diagnostic repetition, not a claim of persistent process/cache warming. No retries or additional samples are added after failure. A failed/inconclusive trial blocks later trials; the independent report retains failed/unstarted slots.

The CPU reference has a 600-second external ceiling. Each of the five GPU trials has a 600-second external ceiling (3000 seconds total); its internal 570-second deadline includes model loading/replay/verification/export and leaves 30 seconds within that ceiling for outer startup/cleanup. This is not a guarantee that startup will fit: external expiry remains non-PASS. Existing five-second shared cleanup applies. Phase 1 and phase 2 remain within 3600/10800 seconds respectively; builds and the 86400-second invocation ceiling remain unchanged. Build/image/package inspection is shared, current and mandatory. Resource admission retains `workstation90`, peak-plus-headroom, one active full-envelope role and unavailable-accounting rejection.

GPU replay synchronizes only at measured interval boundaries, not each decode step. Record decoder elapsed time and the interval through boundary verification/export separately from model/role startup. Boundary outputs must be finite and within CPU atol1e-5/rtol1e-4 or actual-HIP atol2e-5/rtol2e-4; top-one tokens match exactly. Missing/extra boundaries or changed mappings fail. Every trial reports the same reference/workload and a qualified, consistent device/memory envelope.

The frozen measurement mode is `aggregate1Hz/v1`: reuse the existing bounded recorder for CPU consumption, GPU/activity/memory observations and explicit missing-sensor reasons, alongside the aggregate memory watchdog. No detailed token trace is collected. Record actual Torch thread settings. Verified elapsed time includes recorder shutdown/export. Observation overhead has not been calibrated against an ordinary complete-work arm; these are observational viability/bounding measurements, not production confirmation or a measured speedup.

Only if cold, warmup and all three repetitions complete may the report derive a baseline-only duration reservation using the existing rule: `ceil(max(60, 2*max(three_verified_intervals)))`, capped at 600 seconds. Otherwise calibration is INCONCLUSIVE. No role-startup, encoder, model-generated coverage, fitting, independent scoring or complete-control cost is inferred from this component interval. The report always states `optimization_adoption=false` and `research_cost_admission=false`. It cannot admit a candidate or study; those require separately frozen contracts and the original full-pipeline/cost gates.

One bounded archive retains scope, source, workload/reference identities, per-role resource/device/isolation/cleanup records, boundary output hashes, timing and missing-trial reasons. The original 32-prompt/576-attempt and full-control stress denominators and all historical outcomes remain in their original archives, not relabelled as replay completion.

Each reference/trial durably plans all 12 boundaries before its work. Bounded coarse events distinguish queued-but-unverified output from verified completion; they do not synchronize or trace every token. A terminal boundary report preserves complete, incomplete and unstarted cases on ordinary failure. An externally killed role may lack a terminal record: the durable plan/progress remains partial and cannot be inferred complete. Verified timing includes the terminal boundary export as well.
