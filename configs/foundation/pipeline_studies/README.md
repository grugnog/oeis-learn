## Host input assembly

`inputs-*.example.json` are editable **blueprints**, not runnable manifests. Replace
all file paths and image placeholders with actual inputs, freeze reduced quotas
and budgets, and use `scripts/generalization_inputs.py study`. No example contains
checkpoint bytes or a fabricated initializer. Paths are relative to the checkout.

The `cells` list is the existing bounded materialization plan: training cells may
use frozen descriptor/counter `refresh` settings; other cells name mechanically
generated candidate files. Native/reference admission, coverage, exclusions and
actual model storage remain canonical `generalization preflight/prepare` gates.
Assembly is labeled ASSEMBLED, never PASS or HIP-qualified. Refresh examples must
supply enough unique, mixture-matched accepted rows to cover their token cap.

The E0 example uses the uniform import's original recipe. The other cases can use
a reduced model recipe. P4 must use a compatible, independently selection-designated
literal initializer; a historical best-loss label is insufficient. Its paired batch
must have at least four examples to exercise the 25% replay policy. Parameter-target
acceptance must contain at least one supported, nonzero-parameter learning target.

An optional `feature` path names the original completed `feature.json` in the
qualification root for research-purpose assembly. It is resolved against that
producer root during consumption. Assembly does not manufacture feature proof or
authorize research. P0 stays on the historical `pilot-followup --arms uniform` path.
